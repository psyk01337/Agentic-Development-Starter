# Project Intakes

Raw requirement documents land here before they become repo truth.

An intake is whatever arrived: a customer brief, a ticket export, a customer complaint, a
competitor teardown. Keep it verbatim. When its content is routed into `docs/prd.md`, the
intake stays as the record of what was actually asked for, because the PRD is an
interpretation and interpretations drift.

Name it `<project>-<date>.md`. Conflicting intakes are resolved in the PRD, not by editing
history here.
